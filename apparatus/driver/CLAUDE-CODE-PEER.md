# Synthetic surface-check peer

`claude_code_peer.py` rehearses the controller using the actual gated Stewart
relay and hook helpers. It is a synthetic replacement for the CLI process;
it never invokes Claude, reads credentials or grants invocation authority.
Its checks come from the [runtime contract](../../docs/claude-code/CONTRACT.md)
and [private helper interface](../../docs/claude-code/RUNTIME-REFERENCE.md#private-helper-transport-for-independent-fixtures).
The [independent observer](CLAUDE-CODE-OBSERVER.md) owns the fixture and assesses
the controlled attempts. Fixture effects remain separate from service effects.

```sh
python3 -I -B apparatus/driver/claude_code_peer.py --self-test
```

The self-test uses supplied environments, synthetic frames and mocked helper
transports. It starts no process or socket. It retains the checks, source and
mock traffic, including positive, denial and invariance comparisons. Actual
helper operation and group stopping require the controller's native rehearsal.

## Controller interface

The controller generates an executable shell wrapper whose final command is:

```text
ABS_PYTHON -I -B ABS_PEER --witness-root ABS_ROOT \
  --environment-witness ABS_SNAPSHOT --scenario normal -- ARGV...
```

`normal`, `bad-init` and `wrong-auth` are the only scenarios. The wrapper uses
`/usr/bin/mktemp` to create a unique private snapshot directly under `ABS_ROOT`,
then writes `/usr/bin/env -0` to it before executing Python. It forwards the
original arguments with `"$@"`. Freeze the exact wrapper, interpreter, peer and
imported source files with the commission. No ambient environment is used to
construct the supplied launch environment.

The snapshot observes the environment **after shell startup, before Python**.
Its full raw bytes and decoded mapping are retained. Comparison excludes exactly
the existing driver's named wrapper set: `PWD`, `OLDPWD`, `SHLVL`, `_` and
`__CF_USER_TEXT_ENCODING`. These shell/platform additions remain visible in the
witness; this scope does not establish their presence before shell startup.
After excluding those names, the snapshot must contain exactly the fifteen
specified names and values, including the three bound absolute directories.
Duplicates, incomplete NUL framing, changed `LANG`, extra `LC_CTYPE` or any
other extra variable are refused. The later interpreted environment is retained
separately; a Python locale mutation never excuses a difference in the initial
snapshot. Helper subprocesses receive exactly the validated fifteen-field
environment, without the excluded wrapper names.

After `--`, accept only `auth status` or the complete model argv generated by
the surface fixture. This rehearsal uses no optional effort argument. The peer
infers the family from the exact system-prompt bytes and the model from the sole
`--model` value. It validates the full argv, settings and MCP configuration,
including the writer's quoted hook command and exact helper arguments. Unknown
or repeated peer flags and changed supplied files fail.

The writer must be an absolute regular file containing the gated binary's
static markers. Only `[writer, __stewart-cc-relay, m]` and
`[writer, __stewart-cc-hook, h]` are launched, without a shell or new process
group. Its digest is retained and rechecked before each start. Marker checks
catch mistaken inputs; the controller's immutable binary pin supplies the
identity binding. Markers do not authenticate an arbitrary executable.

Authentication prints exactly `loggedIn`, `authMethod` and `configDirectory`.
The `wrong-auth` scenario changes `authMethod` to `api-key`; it invokes no
helper. No raw authentication stdout, stderr or output digest is retained by
the peer. The controller must keep this invocation's output private too.

## Model comparison and coordination

The model peer reads exactly one complete synthetic input through EOF. It
initializes MCP, sends the initialized notification, verifies the entire tool
inventory and emits startup with version `synthetic-surface-check`.
`bad-init` changes only its `apiKeySource` to `environment`; the observer must
refuse it and the controller must stop the group.

The case key is `sha256(os.fsencode(cwd)).hexdigest()`, using the resolved current
directory. The session ID is `synthetic-surface-` followed by that key. After
emitting startup the peer waits for:

```text
ABS_ROOT/CASE_KEY/startup-observed.json
```

Its exact JSON value is `{"session_id":"EMITTED_SESSION_ID"}`. The controller's
**synthetic-only** stdout callback publishes this file atomically, with no
overwrite, after `observer.feed` returns with valid startup. This coordinates
rehearsal scheduling. It is not a real-harness barrier or an enforcement
observation, and real mode must not publish it. A missing or different
acknowledgement fails within the peer's deadline; the observer's failed startup
must stop the process sooner.

After the acknowledgement the peer emits an assistant tool-use event and
passes the correlated session, tool-use ID, prefixed `record_account` name and
exact synthetic marker to the actual hook helper. An allow reply causes one
MCP call; the expected response reports the fixture effect. A deny reply causes
no MCP call. Both paths close the helper input pipes, observe helper EOF and
successful exits, and emit one final synthetic result. The fixture separately
retains its effect evidence. No peer-reported success substitutes for that
independent observation.

The peer allows fifteen seconds from model-input reading through helper work,
with at most one further second per started helper for TERM/KILL cleanup.
Frames are bounded at 8 MiB, hook replies at 64 KiB and journal writes at 32 MiB.
Partial reads and writes remain witnessed. Nonblocking polling protects against
ordinary readiness races; it cannot bound a stuck kernel call, process creation
or filesystem operation. The controller must retain its independent watchdog
and observe the entire group absent. Failed cleanup reports uncertainty and
must prevent another invocation.

## Retained witnesses

The case parent may already exist for the synthetic acknowledgement. Its `auth`
and `model` directories must each be fresh; repeated use is refused. Each
contains `invocation.json`, `environment-initial.bin`, `environment-initial.json`,
`validated.json`, supplied
settings/MCP/system files, five source snapshots and `events.jsonl`. Events name
their observer PID and shared kernel clock.

The model directory additionally retains raw model input/output, relay and hook
input/output, the received startup acknowledgement and `RESULT.json` on success.
`supplied`, `sent` and `received` suffixes distinguish intended bytes, confirmed
writes and observed reads. Helper exit observations are journal entries.
`FAILURE.json` preserves ordinary failure details; an externally stopped process
may leave only the preceding phase and byte witnesses. Missing completion is
not success. No socket or other special file is created under this evidence
root. The peer produces no eligible profile observation or reviewed check.
