# Commission intake and a real self-audit

C is independently usable for manager-custodied delivery of an original
commission, detailed receipts and verified readback. Its acceptance means the
selected originals were delivered, not that an audit launched or a result was
preserved. The user explicitly selected that custody boundary before implementation.
The [user guide](../../successor/README.md) states the interface and limits.

The subsequent self-audit found and led to two narrow corrections. A fresh
manager recovered the actual commission after a constructed context discontinuity.
A different fresh investigator examined the actual preserved return without its
original writer or working environment. **No additional product feature is
warranted by this case.** The finite delivery inventory and existing inspection
tools met the demonstrated need. No A preview, result producer/reader, result
schema or new custody service was implemented.

## What shipped and was checked

The Rust binary provides `accept`, `complete`, `inspect`, `read` and `abandon`
for finite original-file selections. It preserves exact request bytes, binds
expected and observed selections, publishes completion last through exclusive
receipts, supports explicit incomplete-intake completion/disposition, and reads
retained originals without consulting their old source paths. Mutations remain
writer-bound; supported readback is independent. It never deletes a bundle.

Final release SHA-256:
`dbcf332cbba5ecf7ee74491ffe80875df82af64418b09215d9f6ca22459d8bbd`.
Implementation commit `0dbb2eb`; repair commit `075f4d3`. These are local Apple
Silicon macOS qualifications with Rust 1.99.0, not Linux/WSL, hostile-host,
historical-authentication or hardware-durability claims.

## The genuine commission and fresh manager

The [actual question](../../audits/commission-recall/PROMPT.md) is a bounded
Information preservation audit of C's requested undertaking, completed delivery,
incomplete intake and present readback distinctions. It serves the real decision
whether to rely on the first release or repair/narrow it. Static inspection and
the issued helpers were granted; a favorable result, execution, repairs, expanded
source access and delegation were not. The target was `0dbb2eb`, with prompt
commit `e906095` and the exact selected observations retained in the commission.

Before launch, C accepted the actual prompt, 53 subject/evidence members and
three guidance/handoff members. The [commission bundle](commission/ACCEPTED.json)
has external receipt pin
`8b5c73b84f1c729f96390d4fcdfb4acfc9c62e6036528c39002226043762680f`.
Root kept an independent exact-byte witness outside the audit environment.

The [fresh manager](../../coordination/commission-intake-01/manager/RECOVERY.md)
received only the standard bundle reference/pin, reader and guide. It recovered
the original question, decision, selection/views, guidance, grants, limitations
and stop condition. Its 58 pinned reads all succeeded; root independently matched
the exact selection and bytes afterward. This was a real fresh context with no
original conversation, not a forced harness compaction or a memory-service test.
Finite read grants and reported read accounts do not establish OS enforcement.

## What the auditor found and what changed

The [unchanged audit report](audit-return/files/0000.md) returned a complete
bounded static answer. Its declaration matches the collected identities. The
auditor reported 53/53 input verification and disclosed one refused, mistyped
declaration-helper identity, then corrected it. Completion and matching identity
are attributed records, not a grade of the answer.

The report supports accepted-bundle recall within its stated evidence limits.
It identifies a reader-presentation loss after valid incomplete acknowledgment:
the original request stayed in the intent but disappeared from ordinary
inspection. It also identifies an unsupported guide statement that file modes
are recorded. The auditor correctly labels the first as a source prediction,
with no historical post-abandon reader observation in its granted packet.

Root confirmed the proposed comparison after the audit stopped, then repaired
inspection to retain the validated request and corrected the mode wording.
Acknowledgment still does not become acceptance, damaged intent remains diagnosed,
and raw incomplete-material retrieval was not added. The original report,
historical source selection and receipts were not rewritten to describe the fix.
The later binary independently read the earlier actual commission's exact
question/request with the original pin, without executing the original writer.

## Later investigator: needs, support and limits

The [investigator](../../coordination/commission-intake-01/investigator/INVESTIGATION.md)
saved its [needs](../../coordination/commission-intake-01/investigator/NEEDS.md)
before opening the delivery. It then received only the finite package, original
commission, two distinct pins, later C reader and reading guide. No original
writer/runtime, worktree, private session, Git history, parent conversation,
root's substantive triage or post-audit repair evidence was granted. Its actual
reads and instrumentation failures are recorded separately from product outcomes.

| Needed for the historical release decision | What the available selection established | Remaining limit |
| --- | --- | --- |
| Original undertaking | Exact prompt/request and selected material, with declared scope and guidance; prompt digest matches the report's declaration. | No general reconstruction of unsupplied environment or original conversation. |
| Actual returned answer | Four exported authored files, both external pins, and exact source-receipt/report binding verified. | Digests and recorded attribution do not authenticate actor honesty or every historical capture operation. |
| Basis for the reported gap | Historical source shows the omitted incomplete-state projection while retaining request bytes; preserved streams support the stated earlier conditions. | No historical post-abandon inspect/read stream was supplied. The investigator did not promote static prediction into runtime observation. |
| Present commission recall | The later reader recovered exact raw request and question; independent retained-byte comparisons agree. | This does not prove behavior of the old binary, all incomplete states, hardware durability or other hosts. |
| Practical inspection route | Manifest selectors and C inventory resolved numbered files; focused reads overcame metadata-heavy display truncation. | Some manual mapping remained; one case does not establish recurring demand for a product reader. |

The investigator's logger had two Python-wrapper failures and a JavaScript
orchestration failure; those were retained with their actual evidence gaps. Its
three C read/inspect operations succeeded. Reported procedural confinement is
not an independent syscall trace. Root independently checked its recovered
question/request against the withheld original witness and reverified delivery
identities; no required result bytes were missing from the delivered selection.

Root accepts the investigator's bounded conclusion. The existing finite aid
([reading instructions](READING.md), inventory, selectors and distinct pins)
is sufficient for this decision. A reader preview could reduce recurring mapping
work, but would not supply absent observations or execution provenance. No new
result producer/reader or permanent legacy-support promise follows. Revisit only
with a named repeated consumer need or a chosen result-production contract.
Successful result inspection was not used as an acceptance gate for C.
