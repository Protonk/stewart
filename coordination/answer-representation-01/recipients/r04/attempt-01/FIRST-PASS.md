# First-pass decision memo

The supplied return supports a conditional rule for repeating a zero; it does not supply an observed zero to repeat. For this historical implementation, I would accept “zero recomputed disagreements among the complete reviewed ordinary measurements” only for an identified, verified attempt whose non-null ledger has `unmet == []` and `summary.ordinary.mismatches == 0`, with its retained rows and frozen release review identified. I would quote the ordinary comparison count and describe the equality relation. I would separately report process and custody outcomes. This follows the original decision's combined-instrument framing, rather than treating a numeric zero as the proposed rule (context/question.md, “Decision”; answer.md B003, B018–B019).

The gate matters substantively. In the return's P-sub contrast, changing B:strict's measurement ID to strict-v2 preserves the operands, 18-row count, and firing control but changes ordinary counts from four comparisons/one disagreement to three/zero. The discrepancy is excluded from the count, while missing and unexpected IDs make `unmet` nonempty. O-op instead changes the operands to agree and predicts four/zero with an empty gate (B013, B034–B037). Thus a zero can describe a filtered remainder without describing the reviewed population. These are authored predictions, not observations. My static check of context/src/stewart/ledger.py:205–247 supports the mechanism: counted comparisons require a planned ID occurring exactly once, and population selection comes from the supplied review. `prerequisites` at 250–289 covers the membership and sequence anomalies and population/firing thresholds. I found no contrary route within this inspected portion that would let a reviewed missing or duplicated measurement pass the gate.

For an actual claim, I would inspect these items together:

- The attempt identity, implementation/schema provenance, `release_sha256`, and the corresponding release's reviewed cases, populations, expected admissions, and measurement-ID sets. The return expressly assumes the run's review is the validated release review and the attempt comes from the audited version (B004). A digest identifies bytes; it does not independently establish that assumption.
- `ledger.capture`, retained ledger bytes, accepted `rows`, `malformed`, all `anomalies`, and `unmet`. The release determines the expected selector count, not the summary. Empty anomalies alone omit parse failures and firing/threshold conditions. The wrapper explicitly adds parse problems to `unmet` and `errors` (context/src/stewart/experiment.py:510–527; B022, B026–B027).
- `summary.ordinary.compared` and `mismatches`, plus the expected/actual operands for the named measurements, recomputed under the documented relation rather than trusting their `mismatch` flags. Array order and boolean-versus-number differences matter; object key order does not. Numbers compare after Python decoding, and strings receive no Unicode normalization (ledger.py:32–48; B028).
- Control IDs and operands against their reviewed predictions, followed separately by `errors`, `process`, `endpoint`, and runtime observations. Exit zero does not substitute for the measurement gate. The supplied wrapper test explicitly asserts successful custody alongside a missing measurement and a firing control (context/tests/test_stewart_experiment.py:430–444).

A suitable statement would be: “For attempt A and release R (record digest D), the retained ledger reconciles with the frozen review with no unmet measurement prerequisites. Its N reviewed ordinary comparisons have zero disagreements recomputed from their decoded JSON operands. The named control measurements C disagreed; their relationship to reviewed predictions is [assessment]. Process and custody outcomes are [separate account].” This requires filling the placeholders from actual records, none of which is supplied here. It establishes neither operand truth, scientific coverage, control relevance, nor reference independence. Planned refusals are accounted for by admission outcome, not counted as comparisons (B018–B019; manual Ledger subsection).

Control specificity is the consequential qualification beyond membership. K-swap predicts the same summary and case-level mismatch fields when disagreement moves from strict to canonical, despite a review predicting strict disagreement (B007, B014, B035, B039). Consequently, aggregate firing supports only the existence of a counted control disagreement. I would not silently convert that into evidence that every comparison mode was exercised sensitively. Whether every relied-on mode needs its own firing control depends on the manager's intended inference; it is not necessary to redefine the literal decoded-operand count. The smallest follow-up for a real attempt is to inspect its existing captured control rows against the released predictions. A new execution is unnecessary for that check.

The return establishes an inspectable static account and explicit evidence ceiling. Its declaration of completion means completion within that static boundary (B001–B002), not successful measurements. B021 reports an eight-file identity check, which I did not reproduce. Existing test assertions are written expectations; the selected ones I read do not amount to test observations. The ordinary-substitution and event-order contrasts remain predictions. If empirical discrimination is needed before reliance, a bounded pure-function evaluation of L0, P-sub, O-op, and I-perm would directly compare a firing baseline, membership-only change, operand change, and invariance case, recording selector counts and control outcomes. This is an optional further confidence step, not evidence already delivered (B016, B044; context/recipe.md).
