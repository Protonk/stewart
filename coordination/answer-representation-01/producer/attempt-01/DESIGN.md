# Packet design

This is a disposable representation comparison, not a proposed API or judgment of audit utility. The source question, historical report and both notes remain attributed artifacts. No project code or tests were run. No manager review was read.

## Private assignment map

- `p01`: original report `answer.md` and original notes `notes-a.md`, `notes-b.md`, each byte unchanged.
- `p02`: full common organization, `answer.md`.
- `p03`: the common organization with reviewed-membership support and P-sub/O-op distinction removed from the answer payload, including repeated conclusions and alternative demonstrations.
- `p04`: the full common organization with only support-block order reversed.

Every packet has `READ-MANIFEST.json` enumerating its exact allowed files. The shared `packets/context/` has the original question, historical auditor and manager role files, the exact instrument-discrimination recipe, and eleven pinned source files. The full historical README is available there for static inspection. The full question-type guide is not in recipient view. Context equality is procedural file-list equality over the same files, not OS isolation. Historical roles and commands are artifacts, not operating authority.

## Verbatim common form

Forty-four contiguous source-span blocks partition every byte of the report and both notes exactly once. Blocks are placed under identity/completion/kind, answer, support, qualifications and unresolved work. Their stable neutral labels support citation. Original headings, source citations, report declaration, predictions, qualifications, mistakes and proposed follow-ups remain verbatim. The common form adds only organization, labels, attribution and a warning that historical paths confer no access. It imposes no compulsory finding, remedy or decisive conclusion. The original recorder-origin inference in notes 01 lines 244–247 remains unchanged in every arm.

This reorganization necessarily changes adjacency: qualifications move together and answer passages move together. Those changes are part of the common-form intervention. Common versus original cannot isolate a single stylistic factor. The common form is not smaller, and the original's own report template may already apply presentation pressure.

## Omission construction and limits

The omission removes the principal report argument and proof sketches about reviewed-set membership, the manufactured-zero versus true-zero P-sub/O-op comparison, repeated fixture and table equivalents, repeated-key and self-authorized-omission equivalents, the gate recommendations that redundantly answer the removed claim, and the suggested reviewed-summary wording. The exact source ranges and reasons are in `producer/INVENTORY.json`; full removed passages are in `producer/omitted-passages/`. This includes redundant material in both notes, rather than just deleting the named central contrast.

Cuts are whole source lines. Some lines carry several ideas, so collateral loss is explicit: a line with significant-order qualifications, the mixed K-swap/omit-mode paragraph, the alternate precedence comparison and its interpretation, and portions of acceptance wording disappear with membership support. This is a bounded removal test, not a perfectly isolated semantic intervention. Some surrounding references and original numbering remain dangling. Stable labels have gaps. A recipient may notice incompleteness from that shape; concealment was not an objective.

Baseline ledger rows, operand-sensitive controls, other normalization and invariance evidence, source-derived status, recorder-origin inference, and unresolved-work qualifications remain. References to reviewed predictions, fail-closed invalid reviews, general event ordering and missing measurement-ID syntax remain where they do not state the removed exact-set proof or its manufactured-zero alternative. They are possible reconstruction scaffolding. The identical question, manual, tests and implementation expose enough information to reconstruct the removed conclusion. The study therefore measures removal from answer payload under equal context availability, not complete deprivation of the idea. Recipients should record reconstruction and source-inspection effort.

## Reordering

`p04` reverses the sequence of all support blocks relative to `p02`. Each support body and its label remain byte identical. Identity, answer, qualifications and unresolved-work block order stays unchanged. No line within an authored specimen or event sequence is reordered. The explicit source/packet byte-span map and block digests make this independently checkable.

## Reviewer route

1. Inspect `.scratch/answer-representation-01/producer/INVENTORY.json`. Its private `mapping` identifies arms; `blocks` gives original source line spans and hashes; `arms.*.placements` gives half-open output byte spans and retained source lines. Original p01 file identities are under `arms.p01.files`.
2. Compare a block's packet byte slice with its original source line slice. For p03, concatenate only the listed retained source lines. The numbered originals under `producer/numbered-sources/` provide readable anchors. Original sources remain separately held under `source/original/` as the independent witness.
3. Inspect every cut in `producer/omitted-passages/`, then search p03 for semantic equivalents. The preliminary residual scan and final scan are preserved. The omission still needs independent semantic review; byte checks do not prove that all inferential equivalents are absent.
4. Compare p02/p04 support order, block identity sets and non-support ordering. Then inspect the baseline specimen and contrast tables to confirm no within-specimen reordering.
5. Verify the recipe against `source/context/src/stewart/resources/QUESTION-TYPE.md`, lines 29–61 inclusive; the next heading is excluded. Recipe bytes and digest are in the inventory. Verify that every arm's manifest names the same fifteen context files.

`producer/build.py` is the static construction/check script. It reads only the enumerated frozen source originals/context and the supplied manifest, and writes only packet/producer paths. `build-01.log` records the first construction (122 passing checks). A residual review then removed one remaining table row that claimed empty anomalies meant no listed membership defect; `build-02.log` records the final construction and added omission-slice checks (192 passing checks). There were no failing assertions. `CHECKS.json` preserves each check. These are document identity and transformation checks, not product or harness-enforcement tests. Pytest selectors: 0. Installed-wheel comparisons: 0.

## Consultation and contamination account

Read: the producer brief, commission, source manifest, the three original answer texts, the instrument recipe and question-guide heading locations. All admitted original/context files were read as bytes for hashing/copying; their source identities are in the inventory. Initial read outputs were delivered through the tool transcript; full numbered answer texts and subsequent construction/scan outputs are retained in the producer record. The manifest exposes historical manager-decision metadata, as the brief warned. It was seen during the initial manifest read and not copied into packets or used to repair the auditor's account. This exposure is disclosed rather than claimed absent. The actual heldout review was never opened. No recipient dispatch, nested agents, Git write, product execution, install, or custody operation occurred.
