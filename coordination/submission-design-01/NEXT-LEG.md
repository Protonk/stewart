# Candidate implementation commission for the Opus turnover

Prepared 2026-10-27 in response to “What else do we have left to set into place
before we can do an Opus turnover?” This is the coordinator's recommendation for
discussion, not an implementation commission, launch authorization or turnover
directive. The current TURNOVER remains its consumed stub.

## Recommended useful boundary

Build the successor's first persistent answer-custody and manager-delivery leg.
Connect a new explicit audit identity to its verified original commission from C;
support the decided add/replace/delete, prepare/submit and manager collect
semantics; deliver the finite independent manager copy with verified readback,
honest gaps and supported help/status re-entry. Preserve operation identity across
interrupted calls. Apply this to newly created successor records, not mutation or
reinterpretation of frozen Python lifetimes.

This produces useful retained answers and copies while close/removal remain a
separate implementation leg. Do not label an audit closed while its custody
remains unsettled. The accepted close semantics constrain this implementation's
records and future integration; physical disposal is not needed to prove source-
independent manager readback. Keep an independent witness and make source custody
unavailable to the readback process instead of deleting evidence under test.

## What to settle before dispatch

1. **Approve the bounded deliverable and exclusions.** The user retains this scope
   choice. Recommend the leg above. Live auditor launch/process control, physical
   retirement/removal, full human handback and legacy mutation remain separately
   assigned work, with all existing obligations intact.
2. **Specify the first supported interface and receiving route.** The incoming
   coordinator can own a concrete proposal for the Rust command/tool adapter,
   protected custody location, explicit references, manager destination and
   delivery/re-entry behavior. Actual access and delivered interruption notices
   need evidence; a trusted driver or retained ledger alone cannot qualify them.
   State which participant/integration owns each reference before dispatch and
   which supported call/re-entry exposes its outcome. Exact wire spelling and
   schema are implementation choices within these commitments.
3. **Bound unresolved policy.** Known-selection incomplete closing now has an
   accepted direction. For unknowable selection scope, recommend retaining
   available material and diagnostics and leaving close unfinished until that
   authority is decided. This is a proposed deferral, not a new permanent refusal
   contract. Work outside the helper and broader answer restrictions cannot be
   silently disposed of by defining this leg narrowly.
4. **Fix acceptance and stopping points.** Turn the cases below into a finite
   acceptance population tied to the actual supported interface. Name what requires
   user decision or a separately authorized harness trial. Mechanical choices can
   proceed within commission; changes to promises, access or removal cannot.

The next coordinator need not inherit a new research program before implementation.
The inherited wish for a separate damage/failure sanity check remains relevant:
review the selected leg's concrete failure table before fixing its write protocol.
Preparing a user-relayed Riker consultation is possible under its guide; no message
or independent consultation is commissioned by this note.

## Acceptance to make concrete

- Successful edits survive helper/source loss; exact membership and old-payload
  retention obey the authoring contract. Recheck the relevant prototype controls
  against the integrated boundary instead of importing its 72/72 result.
- Stale preparation refuses; dry run preserves edits; submit versus collect has
  one fixed winner with correct attribution, including an honest empty collection.
- Interrupted add before and after publication exposes its same-operation outcome
  through the supported interface. Deliberate equal-byte addition stays distinct.
  Qualify actual auditor notice/re-entry separately from driver-visible records.
- A fresh manager can discover the explicit audit through help/status and obtain
  the original question, manifest and exact selected bytes through normal actions.
- An independent manager copy verifies without access to audit custody; another
  requested copy uses the same fixed return. A lost reply does not create a new
  return, duplicate an operation or supply closing authority.
- Known missing/corrupt bytes, unknown required identity, failed destination copy
  and unrelated record damage retain their distinct diagnostics and useful access.
- Preserve controls and witnesses outside affected custody; report actual selected
  cases and host/interface limits. Keep C's existing acceptance and frozen Python
  protection within the appropriate regression scope.
