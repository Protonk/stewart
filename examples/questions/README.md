# Worked question examples

These are authored paper fixtures for the three selected families, not outputs
of a Stewart runtime. The invented reminder service supplies a small common
world; alternate returns are permitted. Exact wire replies/settings are still
to be specified under [CONTRACTS](../../CONTRACTS.md) and the
[form brief](../../docs/QUESTION-FORMS.md). Do not treat symbolic handles or
missing runtime settings as runnable input to the existing commission binary.

| Example | Work and inadequate-evidence variant |
| --- | --- |
| [Open inquiry](open/WALKTHROUGH.md) | A broad bug-free request, a bounded source account, and a report-only variant. |
| [Inquiry framing](framing/WALKTHROUGH.md) | A concern about reminders, an attributed working question and investigation; a requirements-only variant. |
| [Comparison](comparison/WALKTHROUGH.md) | A/B tradeoffs against supplied criteria; an absent-B variant that permits inability and one-sided observations. |

[Citation controls](CITATION-CONTROLS.md) distinguish exact quote checking from
semantic support and include empty/conflicting answer cases. Expected substantive
conclusions are never acceptance criteria. The final schema spec must supply real
request/reply and rendering fixtures; these walkthroughs cannot establish a
machine round trip, empty-submission usability or runtime custody.

These examples predate [the interface specification](../../docs/INTERFACE.md).
Their front matter (`stewart: problem/1`, `form:`), material IDs (`m1`) and
`add`/`answer_read` calls are earlier sketches. Under the specification they are
`question/1` front matter, `materials/<name>` sources, `record_artifact` and
`read`. They remain illustrations of expression, not runnable input.
